# 세부 개발문서 — 이번 자비스 구조를 이해하는 순서

[Phase 3 실행서](README.md)의 구현을 예로 설명한다. 정확한 타입·기본값은 DESIGN·SCHEMAS가 기준이다.

## 1. 신경망은 부품이고 RAG는 부품을 연결하는 과정이다

embeddinggemma와 Qwen은 이미 학습된 모델이다. 내부에서 토큰화·위치 정보·어텐션·feed-forward를 계산한다.
이번 개발에서 Q/K/V 층을 새로 만든 것은 아니다. 어떤 텍스트를 모델에 주고, 벡터와 원문을 어떻게 저장하고,
필요한 원문을 어떻게 찾아서 답변에 쓰게 할지를 구현했다. Ollama는 이 모델을 실행하는 프로그램이다.

## 2. R3-01: 질문을 검색 가능한 형태로 준비한다

첫 질문이 “우리 회사 연차 신청 기한은?”이고 다음 질문이 “그럼 어디에서 신청해?”라면
두 번째 문장만 검색하면 대상이 없다. QueryPlan은 앞선 **사용자 질문**을 연결해 연차라는 대상을 보존한다.
과거 AI가 잘못 답한 숫자를 다시 가져오지 않는다. 연차와 병가를 동시에 물었던 상황처럼 대상이 불분명하면 확인한다.
이는 보수적인 규칙과 문맥 연결이다. 인간처럼 모든 질문의 뜻을 이해하는 완성된 분류기는 아니다.

## 3. R3-02·03: 문서를 작은 원문 조각과 검색 벡터로 만든다

문서 제목·문단을 먼저 보고 큰 구간만 나눈다. `5일`과 적용 조건이 멀어지면 답이 틀릴 수 있기 때문이다.
문자 수와 모델 토큰 수는 다르므로 실제 임베딩 요청의 토큰 수를 확인한다. 제목과 입력 접두사도 한도에 포함한다.
원문과 문자 위치는 그대로 보존한다. 검색 벡터는 원문을 찾는 데 쓰는 숫자 묶음이며 원문을 대신하는 문서가 아니다.
문서는 document 형식, 질문은 query 형식으로 넣되 서로 비교할 수 있는 같은 모델/버전을 사용한다.

2026-10-15부터 문서 전용 `document_chunks`는 절 안에서 **문단 → 문장 → 어절 → 문자** 순서로
너무 큰 부분만 더 나눈다. 예를 들어 A 문단 180토큰, B 문단 250토큰은 함께 384토큰을 넘는다.
각각 들어가므로 A와 B를 따로 보관한다. B의 첫 문장을 A 뒤에 억지로 붙이지 않는다.
작은 단위는 묶고, 겹침 때문에 완전한 문단을 깨지는 않는다. 제목·접두사도 예산에 포함된다.

질문 “출장 규정 중 임원 항목은 제외해”는 전체가 하나의 검색 입력이다. 질문에도 토큰화는 필요하지만
문서처럼 여러 청크로 나누지는 않는다. 길이만으로 문서/질문을 판정하면 긴 질문의 제외 조건을 놓칠 수 있다.
따라서 파일 등록과 질문 검색이라는 목적을 먼저 나눈다. 토큰 수는 문서 청크의 크기를 확인하는 기준이다.
FSM은 모델의 이해 기능이 아니다. 이번에는 기존 색인 세대의 준비/활성 상태와 분리된 함수 경로를 사용한다.
PDF는 청크를 만들기 전에 먼저 읽는다. 페이지 좌표를 이용해 반복 머리말·꼬리말을 지우고,
장·조를 Markdown 제목으로, 항·호를 문단으로 바꾼다. 그다음 같은 재귀 청커에 넣는다.
이 순서여야 페이지 아래 문구가 조문 중간에 끼어들지 않고 조항 단위로 검색할 수 있다.
전체 Markdown과 원본 페이지·조항 정보를 DB에 저장하므로 나뉜 청크도 출처를 찾을 수 있다.
장 제목만 있는 구간은 다음 조문 본문에 붙인다. 제목만 검색되는 쓸모없는 청크를 막기 위해서다.
입력은 UTF-8 md/txt와 텍스트 PDF다. OCR은 미구현이며 이미지뿐인 페이지는 오류로 알린다.
[PDF 변경 이유와 실제 테스트](../rag/RAG_PDF_INGESTION.md)를 참고한다.

## 4. R3-04: 새 원문과 새 벡터를 한 세트로 교체한다

규정이 3일에서 7일로 바뀌었는데 원문만 새것이고 벡터는 옛것이면 검색과 인용이 어긋난다.
새 청크·벡터를 준비한 다음 완성된 세트를 한 번에 활성화한다. 이 세트를 generation이라고 부른다.
주 SQLite DB의 원문·FTS·벡터를 함께 전환한다. 별도 semantic DB는 다시 만들 수 있는 사본으로 둔다.
새 세대 준비가 실패하면 이전 완전한 세트를 유지하되, 파일이 이미 바뀌었다면 최신 근거인 것처럼 답하지 않는다.
파일 내용뿐 아니라 청크 설정·모델 버전도 변경 감지에 포함한다.

## 5. R3-05: 검색과 재정렬, 답변 입력은 서로 다른 단계다

FTS5는 단어가 맞는 곳, 벡터 검색은 표현이 가까운 곳을 찾는다. RRF는 두 순위를 합친다.
Cross-Encoder는 질문과 후보 원문을 함께 읽고 다시 순서를 정한다. 모델 한도를 넘는 후보는 여러 구간으로 읽는다.
찾은 조항의 앞뒤가 필요할 수 있어 인접 청크를 더하고, 겹친 원문은 제거한다.
그 뒤 Qwen 입력 예산에 들어가는 근거만 전달한다. 디코더가 문서 DB를 검색하는 단계는 없다.

## 6. R3-06: 근거 답변과 일반 답변을 화면에서 구분한다

문서에 신청 기한이 있으면 그 원문으로 답하고 출처를 붙인다. 문서에 광합성 설명이 없다면
일반 지식으로 답할 수 있지만 “문서 근거 없는 일반 답변”이라고 표시한다.
회사 대표의 연봉처럼 내부 자료가 필요한 질문은 일반 지식으로 채울 수 없으므로 보류한다.
검색 장애나 서로 다른 규정의 충돌도 일반 답변으로 덮지 않는다. 같은 정책을 화면·음성·대화 기록에 적용한다.

## 7. R3-07: 계산을 허용하되 근거를 잃지 않는다

문서의 기본분 5일과 이월분 3일을 합치면 8일이다. 8이라는 숫자가 문서에 없다는 이유만으로 거부하면
RAG가 단순 복사만 하게 된다. 그래서 모델이 피연산자·인용·단위·연산·결과를 제출하고 코드가 직접 계산한다.
잘못된 합계나 원문에 없는 숫자는 거부한다. 두 잔액을 실제로 합쳐도 되는지는 문서 조건과 질문을 다시 검사한다.
같은 모델이 두 번 검사하므로 이 과정이 모든 오류를 잡는다고 보장하지는 않는다.

## 8. R3-08: 코드 성공과 실제 답변 성공을 따로 확인한다

가짜 모델 테스트는 DB 중단·오류·출처·분기 계약을 재현한다. 실제 모델 평가는 모델이 새 JSON 형식을
따르는지, 긴 문서와 후속 질문에서 실제로 올바른 답을 만드는지 확인한다.
이번에는 최초 17개 중 15개가 통과했고, 계산식 누락과 올바른 답의 과도한 보류를 수정한 뒤 다시 평가했다.
평가 자료는 합성 문서이며 운영 대화 DB를 섞지 않았다. 최신 수치와 제한은 [구현 보고](../rag/RAG_R3_IMPLEMENTATION.md)에 있다.


## 2026-10-15 인용·복합 질문 보완

짧은 조문은 같은 장 안에서 최대 4개 묶고, 긴 조문은 재귀로 나눈다. 뒤쪽 조각이 검색되면
같은 조문의 앞부분도 가져와 전제 조건을 확인한다. 모델이 선택한 원문 ID를 앱이 인용문과
조항·페이지로 바꾸므로 출처를 다시 쓰다가 생기던 오류를 줄인다. 여러 질문은 항목별 검색과
검증으로 나눠 한 질문의 숫자가 다른 질문으로 옮겨가는 것을 막는다.
세부 계약·테스트·비교 그래프는 [인용 개선 보고](../rag/RAG_CITATION_FIXES.md)를 따른다.

### RG-PDF-MD: 검색용 원문과 확인용 파일을 같게 둔다

PDF를 다시 별도 변환하면 DB와 `.md`의 내용이 달라질 수 있으므로 게시된 DB Markdown에서 파일을 만든다.
파일은 복구 가능한 사본이며 저장 실패가 검색 DB를 되돌리지는 않는다. 생성 폴더는 색인에서 제외해
같은 조문이 PDF와 Markdown 두 문서로 검색되는 문제를 막는다.
전체 흐름·오류/복구 규약·검증 결과는 [Phase 3 README](README.md)와 [PDF 적용 보고](../rag/RAG_PDF_INGESTION.md)를 따른다.

### RG-ANSWER-QUALITY: 청크 크기보다 근거 전달과 답변 완전성을 먼저 고친다

기존 100문항에서 검증기의 오판, 옆 문단 인용, 복합 질문 누락과 구조 집계 부재를 확인했다.
청크를 더 잘게 나누면 조문의 조건이 흩어질 수 있어 재귀 v4를 유지하고 검색 이후를 보완했다.
원문을 직접 선택하면 불투명한 ID를 잘못 고르는 오류를 줄일 수 있다. 동일 조문·항의 문맥을
보강하되 입력 예산을 지키고, 전체 주기·의무 질문은 관련 구간만 선택한다. 장·조·호 개수는
모델 추측 대신 저장 구조에서 계산한다. 수치 일치와 별개로 의미 검증을 계속 수행한다.
[Phase README](README.md)와 [측정·제한](../rag/RAG_ANSWER_QUALITY.md)이 기준이다.
