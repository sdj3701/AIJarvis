# Post-v1 — 선택 고도화

이 폴더는 후속 제안과 이미 개발에 반영된 기능의 운영 문서를 함께 보관한다.
폴더 이름만으로 미구현이라고 판단하지 않는다. 로컬 임베딩·재정렬은 현재 RAG 기반이며
기본 품질 개선은 [Phase 3 R3-01~08](../phase-03-research/README.md)에서 관리한다.
아래 진입 조건은 새 선택 기능의 후속 릴리스에 적용하며 기존 구현 점검·문서 개정과 구분한다.

## 1. 진입 조건

- [운영 문서](../operations/README.md)의 v1 체크리스트 완료
- 7일 데이터 손상·금지 동작·시크릿 유출 0건
- 추가하려는 기능 하나마다 별도 결정 기록과 위협 모델 검토
- 기존 v1 회귀 테스트를 그대로 유지할 수 있음

## 2. 기능별 분리 원칙

아래 항목을 한 릴리스에 함께 묶지 않는다. 각각 별도 branch·결정·게이트를 만든다.

### 로컬 LLM 후속 고도화 및 도구 제어

- [영구 명령 기억과 문장 임베딩](COMMAND_MEMORY.md): 기존 DB에 확인된 앱 실행 문장을 저장하고
  새 표현을 임베딩 검색·의미 확인 후 재사용하는 구현과 운영 방법.

- [영구 응답 룰북과 결론 한 문장 출력](PROPOSAL_PERSISTENT_RESPONSE_RULEBOOK.md):
  재시작 후 유지되는 룰북과 화면 상세·음성 결론 분리 구현; 실장치 낭독 성능 게이트는 대기.

- [앱 자동 탐색과 최초 실행 승인 저장](PROPOSAL_APP_DISCOVERY_AND_SAVED_APPROVAL.md):
  처음 실행할 때 허용 여부를 묻고, 허용한 앱은 저장해 이후 재질문 없이 실행하는 구현·검증 계약.

- [카카오톡 종료 구현](KAKAOTALK_CLOSE.md): 정적 경로 등록, 정상 종료와 명시적 강제 종료,
  PID·생성 시각에 묶인 승인. Gate A 활성화 없이 명령으로 사용 가능.

- **[제안서: LLM 도구 호출과 동적 애플리케이션 제어](PROPOSAL_DYNAMIC_APP_CONTROL_AND_FUNCTION_CALLING.md)**: Ollama 도구 호출, 동적 앱 탐색, 정상·강제 종료를 별도 게이트로 도입하고 기본 거부 정책과 승인 바인딩을 유지
- **[레거시: 애플리케이션 종료 도구](PROPOSAL_CLOSE_APP.md)**: 이미지명 기반 강제 종료 설계의 이력 문서이며, Gate C·D 제안으로 대체됨
- **[제안서: Ollama 자동 실행](PROPOSAL_OLLAMA_AUTO_LAUNCH.md)**: 백그라운드 모델 서버 헬스체크 및 자동 시작
- D005에서 Ollama + `qwen3.5:9b` 로컬 전용 모드를 Phase 1 기본으로 채택했다.
- 이 절에서는 다중 로컬 모델 라우팅·모델 교체·더 큰 문맥만 후속 기능으로 다룬다.
- 도구 정책과 MemoryStore는 그대로 재사용한다.
- 모델 교체 때마다 hash·출처·라이선스를 새 결정으로 기록한다.
- 12GB VRAM에서 context·STT 동시 실행 benchmark
- 오프라인 상태에서 외부 HTTP가 0건인지 테스트

### 현재 검색 기반과 후속 고도화

- [로컬 임베딩·대화 검색](LOCAL_SEMANTIC_MEMORY.md): 현재 설치·저장·명령·장애 처리
- [RAG 검증](RAG_VALIDATION.md): 기존 실제 모델 평가와 그 한계
- [Phase 3](../phase-03-research/README.md): 질문·청크·입력 형식·색인·근거 답변의 기본 개선
- ANN/규모 확장·모델 교체는 별도 비교 평가 후 결정한다.
- 모델/입력 형식 변경은 버전 분리·재색인이 필요하다. 문서·대화·구조화 기억의 삭제 명령은 각각의 계약을 따른다.

### 외부 서비스 연동

- 캘린더·메일은 읽기 전용으로 시작
- OAuth token은 Credential Manager 사용
- 서비스 응답은 untrusted content
- 쓰기·전송·초대·메일 발송은 별도 High 위험 기능으로 분리
- 최소 scope와 revoke 절차 문서화

### Wakeword 고도화

- 현재 `--voice` opt-in 로컬 “자비스” 호출을 사용자별 호출어로 확장
- 호출 전 오디오는 계속 디스크·API에 저장하지 않음
- 트레이 마이크 indicator와 즉시 끄기 제공
- false activation·background TV 음성 장기 테스트와 임계값 조정

### 피드백 통계

- 좋아요/싫어요는 평가 데이터로만 저장
- 프롬프트·도구 정책을 자동 변경하지 않음
- 통계가 어떤 응답/버전에서 나왔는지 연결
- 개인정보와 raw 보존 정책을 그대로 적용

### 파인튜닝

- 마지막 선택지로 둔다.
- 학습 데이터의 명시적 동의·삭제·익명화·license를 먼저 정의한다.
- RAG·프롬프트·기억 검색으로 해결되지 않는 반복 문제와 충분한 평가셋이 있을 때만 검토한다.
- 운영 시크릿·개인 문서 원문을 학습 데이터로 자동 편입하지 않는다.
