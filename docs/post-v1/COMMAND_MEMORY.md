# 영구 명령 기억과 문장 임베딩

2026-09-09 · 구현: 앱 실행 명령(open_app) · 결정 D022

## 목적과 범위

정규식에 없는 새로운 표현을 매번 코드에 추가하는 대신, 사용자가 확인한 문장과 앱 실행
의도를 기존 SQLite에 저장하고 다음 요청에서 재사용한다. 여기서 학습은 **확인된 사례 축적**이다.
Ollama 또는 임베딩 모델의 가중치를 온라인으로 재학습하는 기능은 아니다.

현재 대상은 앱 실행이며 종료·강제 종료·파일 작업의 학습은 포함하지 않는다.
기존 종료 정책은 그대로 유지한다. 실행 의도 기억과 exe 실행 허용 권한은 다른 저장소·정책이다.

## 처리 순서

1. 새 입력이 기존 정책에 금지되어 있으면 먼저 거부한다.
2. 이미 확인/수정해 저장한 동일 문장의 뜻이 있으면 이를 재사용한다. 그렇지 않은 명확한
   기존 명령 패턴은 현재 실행 경로를 사용한다. 대상이 확인되어 실행되거나 최초 승인을
   기다리는 앱 실행 문장은 `explicit_command` 예시로 저장한다. 이것은 실행 권한 저장이 아니다.
3. 미인식 문장은 인용·부정·질문·조건·다중 작업 등 보수적 필터를 통과해야 한다.
4. 확인된 동일 문장은 DB에서 정확 검색한다. 임베딩 서버가 꺼져 있어도 같은 뜻을 재사용한다.
5. 다른 표현이면 현재 모델의 문장 벡터와 비교해 후보를 찾는다. 다른 앱 이름이 명시된 경우
   기존 후보의 대상 앱으로 바꾸지 않는다.
6. 후보가 없고 실행 의도 표현이 있으면 기존 로컬 LLM 클라이언트로 한 번 분류한다.
   반환 값은 `intent=open_app|none`, `app=이름` JSON으로 제한하고 경로/인자/다중 도구를 받지 않는다.
7. 새 의미는 반드시 “[앱 실행] 뜻인가요?”를 묻는다. `맞아` 확인 전에는 저장·실행하지 않는다.
8. 확인 후 기존 SafetyGate와 ToolRunner로 전달한다. 최초 exe 허용이 없으면 별도 승인 절차다.
9. 확인된 문장을 즉시 트랜잭션으로 저장한 뒤 벡터를 생성한다. 종료를 기다려 저장하지 않는다.

의미 확인은 채널·세션 내 프로세스 상태·120초 만료에 묶인다. 취소/새 요청/문맥 초기화/종료는
대기 상태를 무효화하며 재시작 후 대기를 자동 실행하지 않는다. GUI·음성 턴은 재진입 잠금으로
직렬화한다. 음성으로 확인 안내를 안전하게 전달하지 못하면 대기를 취소한다.

유사도는 실행 권한이나 의도가 맞을 확률이 아니다. 임계값 0.60은 **확인 질문을 제안하는 기준**이고,
유사도만으로 자동 실행하지 않는다. 동일 문장의 재사용에도 앱 파일·경로·해시·허용 정책을 재검증한다.

## 저장 계약

저장 경로는 `settings.paths.data_root / settings.paths.memory_db`다.
현재 개발 환경은 `D:\Ai\Jarvis\data\memory\jarvis.sqlite3`다.
기존 기억 DB의 records/embeddings 테이블을 임의 용도로 바꾸지 않고 다음 확장 테이블을 추가한다.

| 테이블 | 필드 및 규칙 |
|---|---|
| command_memory_meta | key PRIMARY KEY, value; schema_version=1 |
| command_examples | id PRIMARY KEY, phrase UNIQUE(정규 문장), original, tool=open_app, app, provenance, created_at |
| command_vectors | example_id, model, dimension, vector(JSON float 배열); PRIMARY KEY(example_id,model) |

`provenance`는 explicit_command 또는 user_confirmed이며 모델 추측 자체는 저장하지 않는다.
모델 식별자는 이름·Ollama digest·전처리 버전(command-v1)으로 구성한다.
새 digest로 시작하면 기존 의미는 유지하고 새 모델 벡터를 생성하며 서로 다른 공간의 벡터를 섞지 않는다.
동일 문장 정규화는 NFKC·대소문자·공백·마지막 마침표/느낌표 처리로 제한한다.
벡터는 유한수·차원·영벡터 여부를 검사하고 정규화한다.

BEGIN IMMEDIATE 트랜잭션과 UNIQUE 제약으로 중복 저장을 방지한다.
기존 DB 기본 schema_version=1은 변경하지 않고 독립 확장 버전으로 관리한다.
손상·미지원 확장 버전은 오류로 처리하고 기존 DB를 초기화하지 않는다.
확인된 의미 저장 후 벡터 생성이 실패하면 의미는 남고 다음 검색 또는 수동 재색인에서 복구한다.
기존 기억 DB의 백업에 함께 포함된다. 같은 OS 계정에 대한 신뢰 경계는 기존 DB와 동일하다.

## 설정과 설치

```yaml
command_memory:
  enabled: true
  embedding_model: embeddinggemma
  similarity_threshold: 0.60
  timeout_s: 10
  max_examples: 2000
```

기본값과 배포 예시는 false이며 모델 설치 후 활성화한다. 이번 개발 환경에는
`ollama pull embeddinggemma`로 모델을 설치하고 위 설정을 활성화했다.
설치 후 문장 전송은 `http://127.0.0.1:11434/api/embed`로만 이루어지며 프록시·리다이렉트는 차단한다.
기존 `memory.embedding.enabled`는 사실 기억 검색용 별도 설정이며 이 작업에서 켜지 않는다.

확인한 모델 digest: `85462619ee721b466c5927d109d4cb765861907d5417b9109caebc4e614679f1`.
API 계약: [Ollama Embed](https://docs.ollama.com/api/embed),
모델 정보: [EmbeddingGemma](https://ollama.com/library/embeddinggemma).
출력 차원: 768. 콜드 로딩은 10초 제한을 넘을 수 있다. 이때 예시는 보존하고 벡터는 대기로 남긴다.
앱 실행 자체를 임베딩 오류 때문에 실패했다고 표시하지 않으며, `command.memory` 이벤트에
saved/indexed/index_pending/save_failed/search_unavailable/exact_hit/confirm_interpretation을 기록한다.

## 사용법

- `/commands`: 저장된 명령·벡터 건수, 문장→앱 대응, 삭제 ID 확인.
- `/learn 작업 시작 => /open_app discord`: 뜻을 직접 지정해 저장한다. 이 명령 자체는 앱을 실행하지 않는다.
- `/commands reindex`: 현재 모델로 누락된 벡터 최대 16건을 생성한다. 많으면 반복한다.
- `/commands forget ID`: 해당 명령 예시와 관련 모델 벡터를 삭제한다. 실행 중인 앱이나 exe 허용은 변경하지 않는다.
- 잘못된 뜻 수정: 같은 `/learn 문장 => /open_app 올바른앱`을 다시 입력한다.

명령 이름을 모르면 먼저 일반 실행 요청으로 앱을 탐색하거나 `/open_app 앱이름`을 사용한다.
민감정보가 감지된 문장은 이 저장소·임베딩으로 보내지 않는다.
학습을 끄면 저장된 예시를 삭제하지 않고 기존 명령 처리로 돌아간다.

## 검증과 한계

`scripts/tests/integration/test_command_memory.py`에서 재시작 후 정확 재사용, 임베딩 오프라인,
의미 확인/실행 승인 분리, 삭제, 부정·질문·인용 차단, 만료·채널 변경·초기화,
벡터 실패 후 복구, 다른 앱 이름 구분, 모델 변경 재색인, 손상 DB 비초기화를 검증한다.
설정 파일로 기능을 켜는 실제 생성 경로와 재시작 후 오프라인 재사용, 사용자가 수정한
문장 뜻이 기존 파서보다 우선하는 경우도 회귀 테스트에 포함한다.

실환경에서는 사용자가 실제 요청한 “디스코드 실행”을 explicit_command 예시 1건으로 저장했고,
768차원 벡터 1건을 생성했다. 기존 records 38건은 유지됐으며 실행 권한을 대신 부여하거나
사용자 앱을 띄우지 않았다. “디스코드 좀 띄워줘” 유사도는 약 0.697로 후보에 포함된다.
“디스코드 실행하지 마”는 약 0.833으로 더 가깝지만 필터가 검색 전에 차단한다.
이는 유사도만으로 실행하면 안 되는 실측 사례다.

첫 설치 로딩·VRAM 경합·음성 인식 오류는 별도 성능 요인이다. 모든 자연어 명령을 이해한다고
보장하지 않으며 애매한 표현은 재질문하거나 `/learn`으로 명시적으로 가르친다.
현재의 실행 표현 필터와 예시 검색으로 처리하지 못하는 새로운 명령 종류는 실행하지 않고
별도 기능 확장으로 다룬다. 임계값의 전체 한국어 평가셋 최적화는 후속 검증이다.
