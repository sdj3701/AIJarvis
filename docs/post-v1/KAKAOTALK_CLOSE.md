# 카카오톡 종료 구현 결정 (2026-09-09)

사용자의 카카오톡 종료 기능 요청에 따라 정적 허용 목록 기반 종료를 구현한다.
상위 [동적 앱 제안](PROPOSAL_DYNAMIC_APP_CONTROL_AND_FUNCTION_CALLING.md)의 전체
카탈로그 구현과 독립적으로 슬래시 명령과 제한된 한국어 명령을 지원한다.

- `카카오톡 종료해줘`, `카톡 꺼줘`, `/close_app kakaotalk`: medium 승인 후 정상 종료 요청.
- `카카오톡 강제 종료해줘`, `/close_app kakaotalk --force`: high 텍스트 확인 후 종료.
- 정상 종료 뒤 프로세스가 남으면 성공으로 표시하지 않으며 자동 강제 종료하지 않는다.
- 질문·부정문·인용문은 한국어 종료 명령으로 처리하지 않는다.
- 실행 경로는 설정의 app_map에서만 가져온다. 카카오톡의 확인된 설치 경로를 등록한다.
- 종료 어댑터는 Windows API로 동일 사용자 SID·동일 세션·비상승 프로세스만 선택한다.
  보호 대상 explorer와 Jarvis 프로세스/부모는 거부한다.
- 승인 해시에 PID·생성 시각·실행 파일 경로·파일 식별자·종료 방식을 포함한다.
  승인 뒤 대상이 달라지면 재승인이 필요하다. 실행 시 열린 프로세스 핸들로 정체성을
  다시 검증하며, 강제 종료는 그 핸들에만 적용한다. 이미지명/트리 종료는 제거한다.
- 정상 종료는 해당 PID의 최상위 창에 PostMessageW(WM_CLOSE)를 보낸다.
  완료는 실제 프로세스 종료로 판정한다. 트레이 상주로 남으면 강제 종료 명령을 안내한다.
- force는 명시적 명령 파서 경로에서만 허용한다. LLM이 제안한 force=true는 거부한다.
- proc_terminate capability를 요구하며, 기존 proc_spawn 종료 설정은 갱신해야 한다.
- 테스트는 가짜 프로세스 어댑터로 승인/대상 변경/미종료/강제 종료를 검증한다.
  사용자 카카오톡은 구현 테스트 중 종료하지 않는다.

설정 적용 후 Jarvis를 다시 시작한다. GUI 채팅창에서도 안내된 y 또는 확인 문구를
입력해 승인할 수 있다. 확실한 소스 실행은 Jarvis.bat 또는 python -m app --gui로 한다.
scripts/build_exe.py의 런처는 소스를 실행하므로 재빌드가 필요 없다.
롤백은 close_app.enabled=false로 한다. 이전 taskkill 구현으로 돌아가지 않는다.
