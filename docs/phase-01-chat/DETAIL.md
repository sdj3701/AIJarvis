# 세부 개발문서 — Phase 1 대화

> 이 폴더의 [README.md](./README.md)에 적힌 작업을 배경·이유·주의점까지 풀어 쓴 세부
> 개발문서다. 설명은 게임 개발 용어에 빗대어 쓴다. 인터페이스·설정 키·완료 기준의 단일
> 기준은 `README.md`와 기준 문서이며, 내용이 어긋나면 기준 문서를 따른다.
>
> 전체 순서는 [개발 흐름](../DEVELOPMENT_FLOW.md)에서 본다.

## 1. 한 줄 요약

드디어 AI와 대화가 된다. 다만 **말을 걸기 전에 사용자 입력을 먼저 디스크에 저장**하고,
재시도 횟수와 컨텍스트 한도를 엄격히 통제한다.

## 2. 게임으로 치면

외부 서비스(랭킹 서버, 인앱결제)를 처음 붙이는 단계다.

- SDK 래퍼 클래스를 만들고 인터페이스 뒤로 숨긴다
- 테스트용 가짜 구현을 먼저 만들어서 네트워크 없이 개발한다
- 타임아웃·재시도·백오프를 정한다
- 응답 타입이 게임 로직으로 새어 나오지 않게 한다

여기서 "외부 서비스"는 내 PC에 도는 Ollama다. 로컬이지만 HTTP로 통신하니까 붙이는 방식은
외부 API와 같다.

## 3. 무엇을 붙이나

| 항목 | 값 |
|------|-----|
| 런타임 | Ollama, `http://127.0.0.1:11434` 고정 |
| 모델 | `qwen3.5:9b` (약 6.6GB, 4bit 양자화) |
| 컨텍스트 | 16,384 토큰 (모델 최대는 26만이지만 12GB VRAM 기준으로 제한) |
| 비용 | USD 0.00 (로컬이라 API 요금 없음) |
| 클라우드 폴백 | 없음. 외부 호스트로 나가면 거부 |

`127.0.0.1`만 허용하는 건 방화벽 규칙 같은 것이다. 코드 실수나 설정 오타로 내 대화가
외부 서버로 나가는 경로를 애초에 막는다.

## 4. 한 턴의 고정 순서

```text
입력 받음
→ 요청/세션/턴 ID 발급
→ 사용자 입력을 로그 파일에 쓰고 즉시 flush   ← 여기가 핵심
→ 입력 이벤트 기록
→ 대상이 로컬 Ollama인지, 모델 해시가 맞는지 확인
→ 비용 예산 사전 검사
→ 프롬프트 조립
→ AI 호출 (제한된 재시도)
→ 응답과 비용 기록
→ AI 답변을 로그에 쓰고 flush
→ 화면 출력
```

**저장이 호출보다 먼저**라는 게 이 Phase에서 절대 안 바뀌는 규칙이다.

왜? AI 호출은 몇 초에서 몇십 초 걸린다. 그 사이에 크래시가 나면 사용자가 힘들게 쓴 긴 질문이
사라진다. 게임에서 유저가 아이템을 구매했는데 서버 응답 대기 중 앱이 죽어서 결제는 됐고
아이템은 안 들어가는 상황과 같은 종류의 문제다. 그래서 **먼저 기록하고 나중에 처리**한다.

이걸 실제로 20번 강제 종료해서 검증한다(P1-07). 종료 지점 5곳 × 4회 = 20회, 입력 유실 0건이
게이트 조건이다.

## 5. 규칙별로 "왜 이렇게 하는가"

### 가짜 AI를 먼저 만든다 (P1-01)

`FakeLLMClient`를 실제 클라이언트보다 먼저 만든다. 미리 정해둔 답변을 순서대로 돌려주는
스텁이다.

이유는 게임에서 목(mock) 서버를 먼저 만드는 것과 같다.

- 네트워크·GPU 없이도 대화 흐름 전체를 테스트할 수 있다
- 테스트가 빠르고 결과가 항상 같다
- AI가 이상한 응답을 주는 상황을 마음대로 재현할 수 있다

스크립트로 정해둔 답변이 다 소진되면 즉시 예외를 던진다. 조용히 빈 응답을 주면 테스트가
"통과한 것처럼" 보이기 때문이다.

### 재시도할 것과 안 할 것을 구분한다 (P1-02)

| 상황 | 재시도 |
|------|--------|
| 연결 실패, 타임아웃, 서버 5xx | 지수 백오프 + 지터로 최대 횟수까지 |
| 잘못된 요청, 모델 없음, 모델 해시 불일치 | 즉시 실패. 재시도 안 함 |

일시적 장애는 다시 해보면 되지만, **잘못된 요청은 백 번 보내도 잘못된 요청**이다.
재시도해도 안 되는 걸 계속 때리면 로그만 더러워지고 사용자는 몇 배로 기다린다.

"지터"는 재시도 간격에 랜덤을 섞는 것이다. 여러 요청이 정확히 같은 타이밍에 재시도하면
서버가 또 죽는다. 게임 서버 재기동 직후 전 클라이언트가 동시에 재접속해서 다시 터지는
현상과 같아서, 간격을 흩뿌린다.

### 모델 해시를 확인한다 (P1-02)

`ollama list`에 나오는 모델 ID가 결정 기록의 해시 앞 12자리와 같아야 한다. 다르면 실행을
거부한다.

에셋 번들 버전을 검증하는 것과 같다. 모델이 조용히 바뀌면 답변 품질과 VRAM 사용량이 달라
지는데, 원인을 찾기가 매우 어렵다.

### Ollama 응답 타입이 밖으로 새면 안 된다 (P1-02)

Ollama가 준 JSON 구조를 그대로 대화 로직이나 기억 저장소로 넘기지 않는다. 반드시 내부 타입
으로 변환한다.

미들웨어 타입을 게임 로직 전체에 퍼뜨리지 않는 것과 같은 원칙이다. 나중에 모델이나 런타임을
바꿀 때 갈아치울 곳이 한 군데면 된다.

### 컨텍스트를 예산으로 관리한다 (P1-04)

AI가 한 번에 읽을 수 있는 양은 16,384 토큰으로 고정이다. 이걸 시스템 지시·기억·대화 히스토리
같은 블록별로 배분한다.

- 최근 3턴과 현재 질문은 무조건 유지
- 한도를 넘으면 오래된 턴부터 압축
- 입력 자체가 한도를 넘으면 **AI를 호출하지 않고** 사용자에게 알린다

메모리 버짓, 드로우콜 버짓과 완전히 같은 개념이다. 총량이 정해져 있으니 우선순위를 정해서
배분하고, 넘치면 낮은 우선순위부터 버린다. 그리고 예산 초과를 조용히 넘기지 않는다.

### 비용 예산을 요청 전에 검사한다 (P1-05)

로컬 모델이라 단가가 0이지만 구조는 만들어 둔다.

- 요청 전에 **최악의 경우 비용**을 미리 계산해서 검사
- 80%에서 세션당 한 번 경고
- 100%에서 신규 요청만 차단 (진행 중인 건 마무리)
- 금액은 부동소수점이 아니라 `Decimal`로 계산하고 DB에는 문자열로 저장

부동소수점으로 돈 계산하면 반올림 오차가 쌓인다. 게임 내 화폐를 `float`으로 다루면 안 되는
것과 같은 이유다.

"요청 전에 최악 비용을 검사"하는 건 선불 방식이다. 응답이 온 다음 정산하면 이미 초과한
뒤라서 막을 수 없다.

### 취소 토큰을 확인한다 (P1-06)

Ctrl+C 같은 취소 신호를 AI 호출과 프롬프트 조립 지점에서 확인한다. 코루틴 중간에
`CancellationToken`을 체크하는 것과 같다. 긴 작업을 시작 시점에만 확인하면 사용자가
취소해도 몇십 초 더 돌아간다.

### `/clear`는 감사 기록을 지우지 않는다 (P1-03)

`/clear`는 **AI에게 보내는 대화 히스토리만** 비운다. 디스크에 남은 원본 기록은 그대로다.

이건 기능이 아니라 정책이다. 원본 기록은 나중에 "이때 무슨 일이 있었나"를 조사할 수 있는
유일한 증거다. 사용자가 화면을 정리하는 동작으로 증거가 사라지면 안 된다.

## 6. 준비 명령

```powershell
winget install --exact --id Ollama.Ollama
ollama pull qwen3.5:9b
ollama list        # ID가 6488c96fa5fa로 시작해야 함
```

호출 후 `ollama ps`에서 `PROCESSOR 100% GPU`, `CONTEXT 16384`가 보이면 GPU에 제대로 올라간
것이다. `100% CPU`로 나오면 VRAM이 부족해서 CPU로 떨어진 상태라 매우 느리다.

## 7. 다 됐는지 확인하는 방법

```powershell
python scripts\gate.py --phase 1
```

프로토타입 기준으로 이미 한 번 통과한 항목들이다.

- [x] 여러 턴에 걸쳐 문맥이 유지된다
- [x] Ollama 오류가 사용자 메시지와 이벤트로 기록된다
- [x] 20회 강제 종료에서 입력 유실 0건
- [x] 무한 재시도가 없다
- [x] 컨텍스트 압축 후에도 최근 턴이 남는다
- [x] 예산 100%에서 신규 요청이 차단된다
- [x] 실제 모델로 한국어 3턴 대화 성공, GPU 적재 확인
- [x] Ollama 외부로 나가는 HTTP 0건

- 장기 기억을 프롬프트에 넣기 (Phase 2)

- AI가 도구를 호출하려 하면 여기서는 그냥 오류 처리
- 여러 AI 제공자 추상화 확장
