# v2 재구축 안내

이 문서는 기존 프로토타입을 보존한 채 코드를 이해하면서 다시 만드는
`rebuild/v2` 브랜치의 작업 규칙이다.

## 1. 보존 구조

| 대상 | 위치 | 역할 |
|------|------|------|
| v2 소스 | `D:\Ai\Jarvis` | `rebuild/v2`에서 실제 개발 |
| 프로토타입 소스 | `D:\Ai\Jarvis-prototype` | `main` 동결본, 실행·비교 전용 |
| 프로토타입 표식 | Git 태그 `prototype-v1` | 최초 프로토타입 커밋을 영구 참조 |
| 재구축 전 WIP | `wip/pre-rebuild` | 당시 진행 중이던 코드 보관 |

`main`과 `D:\Ai\Jarvis-prototype`에서는 재구축 코드를 작성하지 않는다.

## 2. 데이터 경계

- 프로토타입은 기존 `D:\Jarvis`를 사용한다.
- v2는 개발 중 `D:\Jarvis-v2-dev`만 사용한다.
- 자동 테스트는 pytest가 만든 임시 경로만 사용한다.
- v2가 안정화되기 전에는 프로토타입 데이터의 복사·변환·마이그레이션을 하지 않는다.

v2 개발 환경을 처음 준비할 때는 다음 명령을 사용한다.

```powershell
python scripts\bootstrap.py
python -m app
```

두 명령의 v2 기본 경로는 각각 `D:\Jarvis-v2-dev`와
`D:\Jarvis-v2-dev\config`다.

## 3. 기능 하나의 작업 순서

1. 프로토타입에서 해당 동작을 직접 확인한다.
2. 입력, 출력, 실패 조건을 짧은 문장으로 기록한다.
3. 관련 계약과 테스트를 읽는다.
4. 실패 테스트를 먼저 추가한다.
5. 가장 작은 구현으로 테스트를 통과시킨다.
6. 본인이 코드의 역할과 의존성을 설명한다.
7. 문서를 동기화하고 한 가지 의미만 담은 커밋을 만든다.

기존 코드는 동작 참고자료이지 자동으로 정답으로 간주하지 않는다. 새 구현은
`PLAN.md`, `DESIGN.md`, `SCHEMAS.md`, `TESTING.md`의 계약과 현재 결정 기록을 기준으로 한다.

## 4. 브랜치 규칙

- `main`: 프로토타입 동결. v2가 최소 릴리스 게이트를 통과하기 전까지 병합하지 않는다.
- `rebuild/v2`: 재구축 통합 브랜치.
- `feature/<기능>`: 여러 커밋이 필요한 큰 기능에만 만들고 완료 후 `rebuild/v2`로 병합한다.
- 각 작업 종료 시 테스트를 실행하고 `rebuild/v2`를 원격에 push한다.

## 5. 완료 기준

기능은 다음 조건을 모두 만족할 때만 완료다.

- 역할, 입력, 출력, 실패 경로를 설명할 수 있다.
- 자동 테스트와 해당 Phase 게이트가 통과한다.
- 프로토타입 데이터 `D:\Jarvis`를 읽거나 쓰지 않는다.
- 설정·스키마·운영 문서가 코드와 일치한다.
- 작은 커밋 단위로 되돌릴 수 있다.
