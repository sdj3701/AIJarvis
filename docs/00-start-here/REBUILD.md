# v2 재구축 안내

이 문서는 기존 프로토타입을 보존한 채 코드를 이해하면서 다시 만드는
v2의 작업 규칙이다. 2026-10-16부터 현재 v2 구현을 `main`으로 사용한다.

## 1. 보존 구조

| 대상 | 위치 | 역할 |
|------|------|------|
| v2 소스 | `D:\Ai\Jarvis` | `main`에서 현재 구현 관리 |
| 프로토타입 소스 | `D:\Ai\Jarvis-prototype` | `codex/archive-main-before-v2-20261016` 보관본 |
| 프로토타입 표식 | Git 태그 `prototype-v1` | 최초 프로토타입 커밋을 영구 참조 |
| 재구축 전 WIP | `wip/pre-rebuild` | 당시 진행 중이던 코드 보관 |

`D:\Ai\Jarvis-prototype`은 비교·보관용이다. 현재 개발 위치는 `D:\Ai\Jarvis`다.

## 2. 데이터 경계

- 현재 v2는 `D:\Ai\Jarvis\data`를 실행 데이터 루트로 사용한다(D025).
- 기존 `D:\Jarvis`와 `D:\Jarvis-v2-dev`는 사용자 요청으로 통합했다.
- 자동 테스트는 pytest가 만든 임시 경로만 사용한다.
- `data` 전체는 Git에서 제외한다. 통합 검증과 정리 내역은 [통합 기록](../DATA_CONSOLIDATION.md)에 남긴다.

v2 개발 환경을 처음 준비할 때는 다음 명령을 사용한다.

```powershell
python scripts\bootstrap.py
python -m app
```

두 명령의 기본 경로는 각각 `D:\Ai\Jarvis\data`와
`D:\Ai\Jarvis\data\config`다.

## 3. 기능 하나의 작업 순서

1. 프로토타입에서 해당 동작을 직접 확인한다.
2. 입력, 출력, 실패 조건을 짧은 문장으로 기록한다.
3. 관련 계약과 테스트를 읽는다.
4. 실패 테스트를 먼저 추가한다.
5. 가장 작은 구현으로 테스트를 통과시킨다.
6. 본인이 코드의 역할과 의존성을 설명한다.
7. 문서를 동기화하고 한 가지 의미만 담은 커밋을 만든다.

기존 코드는 동작 참고자료이지 자동으로 정답으로 간주하지 않는다. 새 구현은
`PLAN.md`, `DESIGN.md`, `SCHEMAS.md`, `TESTING.md`의 계약과 현재 결정 기록을 기준으로 한다.

## 4. 브랜치 규칙

- `main`: 현재 v2 구현의 기본 브랜치. 기존 main 이력을 유지한다.
- `codex/archive-main-before-v2-20261016`: 전환 전 main 보관 브랜치.
- `rebuild/v2`: 이전 개발 이력. 원격 브랜치는 보존한다.
- `codex/<기능>`: 별도 작업 브랜치가 필요할 때 사용하고 검증 후 main에 반영한다.
- main 반영 전 테스트와 변경 범위를 확인한다. 이번 전환은 사용자 요청에 따른 것으로,
  실장치 음성·UI 인수나 모든 정적 검사 통과를 의미하지 않는다.

## 5. 완료 기준

기능은 다음 조건을 모두 만족할 때만 완료다.

- 역할, 입력, 출력, 실패 경로를 설명할 수 있다.
- 자동 테스트와 해당 Phase 게이트가 통과한다.
- 자동 테스트가 실제 `D:\Ai\Jarvis\data`에 쓰지 않는다.
- 설정·스키마·운영 문서가 코드와 일치한다.
- 작은 커밋 단위로 되돌릴 수 있다.
