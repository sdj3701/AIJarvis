## 1. 구조를 어떻게 바로잡았는가

| 기존 설명의 문제 | 개정한 설명 |
|---|---|
| 뉴럴 네트워크와 트랜스포머를 별도 부품처럼 취급 | 트랜스포머는 신경망의 한 종류; RAG는 모델·저장·검색·검사를 연결한 시스템 |
| 토큰화를 벡터 변환으로 설명 | 토큰화는 ID 변환, 토큰 임베딩과 문서/질문 검색 벡터는 다른 단계 |
| 위치 임베딩을 어텐션+FFN 또는 단어 의미로 설명 | 위치 정보와 모델 블록을 구분; 모델이 전체 표현을 처리해 검색 벡터 생성 |
| Q/K/V·concat·디코더를 문서 검색으로 설명 | 문서 탐색은 FTS5/벡터 검색·RRF·재정렬; concat은 어텐션 헤드 결과 결합 |
| 자료가 없을 때만 Ollama 사용 | 현재도 임베딩과 답변 생성에 사용; 자료가 있으면 Qwen이 원문을 읽고 답변 |
| 새 AI 답변을 검증된 지식으로 자동 축적 | 미검증 대화 기억으로 보관; 원문 근거·확인된 기억과 구분 |
| 검색 결과 수로 확실성 판단 | 인용 원문·주장 검사 사용; 여러 출처나 높은 검색 점수가 사실 보장은 아님 |
| 0.01초·1024차원·50:50·환각 0 등의 단정 | 현재 768차원/실제 검색 구조와 측정 범위로 수정; 고정 속도·정확도 보장 제거 |

목표 흐름은 다음과 같다.

```text
문서 준비: 원문 → 문맥·토큰 청크 → 문서용 임베딩 → 원문·출처·벡터 색인
질문 준비: 질문 + 필요한 대화 문맥 → 검색 질문 구성 → 질문용 임베딩
문서 탐색: 키워드 + 벡터 → RRF → 재정렬 → 필요한 원문과 주변 문맥 선택
답변 출력: 질문 + 원문 → Ollama/Qwen 생성 → 모드별 근거 검사 → 출처·상태 표시
```

근거 없는 일반 지식은 “문서 근거 없는 일반 답변”으로 표시하는 폴백을 설계했다.
회사 규정·개인 기록의 사실은 자료가 없으면 보류한다. 검색 장애·상충도 별도로 표시한다.
이 폴백은 새 모델 도입이 아니라 기존 로컬 모델을 사용하는 답변 경로 추가이며 **아직 구현 전**이다.

## 2. 실제 코드와 비교해 추가한 개선 작업

| 작업 | 확인한 현재 한계 / 추가할 기능 |

## 4. 검증 범위

- 구조 점검에서 기존 RAG 집중 회귀 75개 통과와 로컬 embedding/reranker 진단을 확인했다.
  새 R3 구현을 검증한 결과가 아니며 기존 전체 평가와 통과 건수를 합산하지 않는다.
- 기존 20문서/200질문 검색 평가와 12건 답변 평가는 과거 실행 기록으로 보존했다.
  현재 소스와 일부 해시가 달라 현재 성능을 보증하지 않는다.
- 기존 문서 23개 수정·이 기록 1개 추가를 작업 전 스냅샷과 비교했다. 변경 문서 24개의
  상대 링크·내부 앵커, 코드 블록 141개의 닫힘, JSON 예제 22개의 파싱, R3/RG 작업 연결을 확인했다.
  새 YAML 설정 예제는 추가하지 않았다.
- 문서 개정 때문에 새 전체 서비스 평가나 정식 릴리스 게이트를 실행하지 않았다.
  앱 코드·설정은 작업 전 해시와 비교해 변경하지 않았음을 확인했다.

위 내용은 문서만 개정한 당시 기록이다. 이후 R3-01~07 구현과 R3-08 자동 평가·운영 문서를 적용했다. 최신 상태는 [PROGRESS](../PROGRESS.md)를 따른다.
