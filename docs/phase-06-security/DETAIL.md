## 1. 한 줄 요약

**새 기능을 하나도 안 만든다.** Phase 0~5에서 만든 걸 공격자 관점으로 두들겨 보고, 백업에서
실제로 복원되는지 확인한다. Critical/High 결함 0건 + 복원 성공이 v0.5 출시 조건이다.

## 2. 게임으로 치면

출시 직전 **컨텐츠 락(content lock) 후 QA·펜테스트 기간**이다.

- 기능 추가 금지, 버그만 잡는다
- 치터 관점으로 클라이언트를 뜯어본다
- 세이브 데이터 손상·복구 시나리오를 실제로 굴려 본다
- 결함 등급을 나누고, 출시를 막는 등급을 정한다
- 릴리스 매니페스트(빌드 번호·버전)를 남긴다

**"기능은 다 됐고 QA만 남았다"고 하는 그 기간이 이 Phase다.** 게임 개발자면 이 기간이
얼마나 중요하고 얼마나 자주 압축되는지 알 것이다. 그래서 문서가 아예 별도 Phase로 못 박았다.

## 3. 결함 등급과 출시 처리

| 등급 | 예 | 출시 처리 |
|------|-----|-----------|
| Critical | 승인 없이 금지 작업 실행, 시크릿 외부 전송 | 즉시 차단 |
| High | 샌드박스 우회, 티켓 재사용, 복원 불가 | 차단 |
| Medium | 오류 메시지 부족, 우회 불가한 성능 문제 | 수정 계획과 기한 필요 |
| Low | 문서·표시 문제 | 다음으로 미룰 수 있음 |

게임에서 A/B/C 등급 버그를 나누고 "A는 출시 블로커"로 정하는 것과 같다.

## 5. 규칙별로 "왜 이렇게 하는가"

### 테스트 없는 High 위협은 출시 차단 (P6-01)

위협 모델의 각 항목은 네 가지를 다 가져야 한다.

```text
예방 통제 (막는 방법)
탐지 통제 (뚫렸을 때 아는 방법)
테스트 (실제로 막히는지 증명)
잔여 위험 (못 막는 부분을 솔직히 적기)
```

"막았습니다"라는 말만 있고 재현 테스트가 없으면 통과가 아니다. 게임에서 "그 치트는 막았어요"
라고 하는데 재현 케이스가 없으면, 리팩토링 한 번에 다시 뚫린다.

`planned` 상태의 위협은 아래 셋 중 하나로 바뀌어야 한다.

| 상태 | 뜻 |
|------|-----|
| `verified` | 코드와 테스트가 있고 통과 |
| `accepted residual` | 완화 후 남은 위험을 사용자가 명시적으로 수용 |
| `blocked` | 검증 실패로 출시 차단 |

Critical/High를 `accepted residual`로 처리하려면 이유·영향·대체 통제·재검토 날짜를 따로
기록해야 한다. **"어쩔 수 없죠"로 넘어가는 경로를 막은 것이다.**

### 시크릿 유출을 전 경로에서 검사한다 (P6-03)

같은 테스트용 가짜 키를 아래 모든 경로에 집어넣고 원문이 안 나오는지 확인한다.

| 경로 | 기대 결과 |
|------|-----------|
| AI 요청 메시지 | 차단 또는 마스킹 |
| 검색 API 질의 | 차단 또는 마스킹 |
| 이벤트/원본/감사 로그 | 마스킹 |
| 기억 레코드 | 저장 거부 또는 민감도 상승 |
| 음성 낭독 | 낭독 거부 |
| 예외 메시지·스택 트레이스 | 원문 없음 |
| 백업 산출물 목록·로그 | 원문 없음 |

**스택 트레이스가 특히 자주 빠지는 경로다.** 예외 객체에 설정값이 담겨 있으면 크래시 로그에
키가 그대로 찍힌다. 게임에서 크래시 리포트에 서버 인증 토큰이 같이 올라가는 사고와 같다.

탐지기의 오탐(false positive)·미탐(false negative) 샘플도 따로 기록한다. 필터가 너무
공격적이면 정상 문장이 막혀서 사용자가 필터를 끄게 된다. 그게 더 위험하다.

### 감사 로그 검증기는 로그를 수정하지 않는다 (P6-04)

```powershell
python scripts\gate.py --verify-audit
```

검증기가 하는 일:

1. 날짜별 파일을 순번대로 읽는다
2. 파일이 바뀌는 경계에서도 이전 해시가 이어지는지 확인한다
3. 정규화 JSON으로 해시를 다시 계산해서 비교한다
4. 누락 순번, 중복 순번, 변조된 줄, 깨진 마지막 줄을 **구분해서** 보고한다

4번의 "구분"이 중요하다. 깨진 마지막 줄은 크래시의 정상적 흔적이고, 중간에 변조된 줄은
공격 흔적이다. 같은 에러로 처리하면 진짜 문제를 놓친다.

그리고 **검증기는 로그를 고치지 않는다.** 자동 복구하면 증거가 사라진다.

### 백업 순서에서 평문을 남기지 않는다 (P6-05)

```text
1. 설정과 대상 위치 확인
2. SQLite 온라인 백업 API로 일관된 DB 사본 생성
3. 원본 로그·설정을 임시 폴더에 복사
4. 매니페스트에 경로·크기·SHA-256·스키마 버전 기록
5. 암호화
6. 별도 저장 위치로 복사
7. 복사된 암호화 파일의 해시 재검증
8. 평문 임시 폴더 즉시 삭제
9. 백업 결과 이벤트 기록
```

포인트 세 개:

- **2번**: DB 파일을 그냥 복사하면 안 된다. 쓰기 중인 순간에 복사하면 반쯤 쓰인 상태가
  백업된다. SQLite 온라인 백업 API를 써야 일관된 사본이 나온다. 게임에서 세이브 중에 파일을
  복사하면 깨진 세이브가 백업되는 것과 같다
- **7번**: 복사한 뒤 대상 위치에서 해시를 다시 확인한다. 복사 중 손상을 잡는다
- **8번**: 평문 임시 폴더를 반드시 지운다. 암호화 백업을 만들었는데 평문이 옆에 남아 있으면
  암호화한 의미가 없다

백업 암호는 명령 인자·환경 변수·파일에 두지 않고 Windows 자격 증명 관리자에서 읽는다.
명령 인자는 프로세스 목록에 그대로 보인다.

### 백업 성공이 아니라 복원 성공이 기준이다 (P6-06)

이 Phase의 철학이 여기 다 담겨 있다.

```powershell
python scripts\backup.py restore --archive <file> --target D:\JarvisRestoreTest
```

**운영 폴더 위에 바로 복원하지 않는다.** 빈 새 폴더에 복원한다. 검증 순서:

1. 새 대상이 비어 있는지 확인
2. 복호화 후 매니페스트 해시 확인
3. SQLite 무결성 검사
4. 스키마 버전 확인, 필요하면 마이그레이션 사전 보고
5. 원본 로그 유효성 검사
6. 설정 시크릿이 백업에 안 들어갔는지 확인
7. 테스트 모드 앱으로 **기억 검색을 실제로 한 번** 해본다
8. 여기까지 다 되면 복원 완료 보고

7번이 핵심이다. 파일이 복원됐다고 앱이 그 데이터를 쓸 수 있다는 뜻이 아니다.
게임에서 세이브 파일 복원 후 실제로 게임을 켜서 로드해 보는 것과 같다.

운영 폴더에 직접 복원하지 않는 이유는, **복원이 실패하면 원본까지 잃기** 때문이다.

### 공급망 검토 (P6-07)

| 확인 항목 | 왜 |
|-----------|-----|
| 해시 lock으로 설치가 재현되는지 | 같은 lock에서 다른 코드가 설치되면 안 됨 |
| 미사용 의존성 제거 | 안 쓰는 라이브러리도 공격 표면 |
| 예제 설정 전부 로드 확인 | 문서와 코드 불일치 방지 |
| `dev_mode=false`에서 `.env`·테스트 훅 비활성 | 개발용 뒷문이 출시 빌드에 남으면 안 됨 |
| 도구 기본 거부와 금지 항목 변경 불가 | 정책 완화 경로 차단 |
| 설정·프롬프트·스키마 버전 매니페스트 기록 | 나중에 "어느 버전이었나" 추적 |

`dev_mode=false`에서 테스트 훅이 비활성인지 확인하는 건 **디버그 명령이 출시 빌드에 남아
있는지 확인하는 것**과 정확히 같다. 게임에서 치트 콘솔이 출시 빌드에 살아 있어서 유저가
찾아내는 사고는 흔하다.

## 6. 다 됐는지 확인하는 방법

```powershell
pytest -m "not allow_network"
python scripts\gate.py --verify-audit
python scripts\gate.py --report
python scripts\backup.py restore --archive <test-archive> --target <empty-test-root>
```

정량 기준: 복합 작업 50건 중 **95% 이상 성공**, 금지 동작 0건, 중복 부작용 0건.

게이트 항목:

- [ ] 느린 테스트까지 포함한 전체 pytest 통과
- [ ] Critical/High 0건
- [ ] 위협 모델의 모든 High 행에 테스트 연결
- [ ] 감사 체인 변조 탐지 성공
- [ ] 별도 위치 복원 후 기억 검색 성공
- [ ] 복합 작업 50건 95% 이상
- [ ] v0.5 릴리스 매니페스트 작성

## 8. 이번엔 안 하는 것

- 보안 테스트를 통과시키려고 기능을 몰래 삭제하기
- 운영 폴더에 직접 복원하기
- 평문 백업을 남겨두기
- Medium/High 결함을 문서 없이 예외 처리하기

첫 항목이 재미있다. **테스트를 통과시키기 위해 기능을 지우고 그걸 숨기는 것**을 명시적으로
금지했다. 게임에서 버그 있는 컨텐츠를 조용히 비활성화하고 "수정 완료"로 처리하는 것과 같다.
지우는 건 괜찮지만 숨기면 안 된다.
