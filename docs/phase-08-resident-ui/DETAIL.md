## 1. 한 줄 요약

터미널을 안 열고 트레이 아이콘과 전역 단축키로 자비스를 부른다. 설치 패키지를 만들고,
Windows를 재시작해도 데이터가 안 깨지게 한다. **여기까지가 v1 후보다.**

## 2. 게임으로 치면

**출시 빌드를 만드는 단계**다.

- 런처/오버레이 UI
- UI 상태 머신
- 전역 핫키 등록
- 인스톨러 빌드 (한 명령으로 재현 가능하게)
- 클린 머신에서 설치 테스트
- 버전 매니페스트
- 세이브 마이그레이션과 롤백 검사

게임 개발에서 "기능은 다 됐는데 빌드·설치·업데이트에서 두 달 잡아먹는" 그 단계다.

## 3. UI 상태 머신

```text
Starting → Idle
Idle → Listening → Transcribing → Thinking
Thinking → ApprovalWaiting | Acting | ShowingResult | Error
ApprovalWaiting → Acting | Idle
Acting → Thinking | ShowingResult | Error
ShowingResult → Idle
Error → Idle | ShuttingDown
```

규칙 두 개:

- 허용되지 않은 전이는 **로그를 남기고 무시**한다 (조용히 무시하지 않는다)
- 같은 시점에 상태는 **하나만** 존재한다

게임 UI 스테이트 머신과 완전히 같다. 상태가 둘 다 활성인 순간이 생기면 "로딩 중인데 입력이
먹는" 종류의 버그가 나온다. 여기서는 그게 **"승인 대기 중인데 다른 작업이 실행되는"** 문제로
나타나기 때문에 훨씬 위험하다.

## 4. 규칙별로 "왜 이렇게 하는가"

### UI가 내부 로직을 직접 부르지 않는다 (P8-01)

```text
금지:   UI가 AI 클라이언트·기억 저장소·도구 실행기를 직접 import
허용:   UI는 이벤트만 받고, 공개 계약으로만 요청
```

게임에서 UI 스크립트가 게임플레이 시스템을 직접 조작하지 않고 이벤트/커맨드로 소통하게 만드는
것과 같다. 여기서는 이유가 하나 더 있다. **UI가 정책 엔진을 우회하는 경로를 원천 차단**하는
것이다.

승인 요청에도 위험도와 표시 문구만 넘긴다. 실제 경로나 권한 정보는 안 넘긴다.

UI 스레드와 작업 스레드 사이에는 스레드 안전 큐를 쓴다. UI 스레드에서 무거운 작업을 하면
화면이 멈추는 것, 게임에서 메인 스레드를 막으면 안 되는 것과 같다.

### 트레이 아이콘이 사라져도 유령 프로세스가 남으면 안 된다 (P8-02)

필수 메뉴:

- 자비스 열기
- PTT 시작/중지
- 현재 상태
- 미완료 작업 확인
- 자동 시작 설정
- 로그 폴더 열기
- 종료

트레이 앱에서 가장 흔한 버그가 "아이콘은 없는데 프로세스는 살아 있는" 상태다. 그러면
사용자가 종료할 방법이 없고, 마이크가 켜져 있을 수도 있다. 작업 관리자로 죽여야 하는 앱이
되면 안 된다.

### 단축키 등록 실패로 앱을 죽이지 않는다 (P8-03)

전역 단축키는 다른 앱이 이미 쓰고 있을 수 있다. 그때:

- 등록 실패를 감지하고
- 앱을 종료하는 대신 설정 화면에서 변경을 요청한다
- 두 번째 인스턴스가 단축키를 다시 등록하지 못하게 한다
- 키 반복 입력을 debounce한다
- 텍스트 창 호출 단축키와 PTT 단축키를 구분한다

키 반복 debounce는 게임에서 버튼 연타를 흡수하는 것과 같다. 단축키를 꾹 누르고 있으면
Windows가 반복 이벤트를 계속 보내는데, 그때마다 새 요청이 생기면 안 된다.

### 승인 창을 알림으로 대체하지 않는다 (P8-04)

- 위험도, 정확한 대상, 예상 변경, 만료 시간을 표시한다
- 표시 문구는 Safety Gate가 만든 값을 **그대로** 쓴다 (UI가 다시 만들지 않는다)
- high는 문구 타이핑 입력만 받는다
- **창 닫기·타임아웃·새 요청은 모두 거부로 처리한다**
- 승인 창을 백그라운드 알림만으로 대체하지 않는다

"창 닫기 = 거부"가 중요하다. 기본값이 승인이면 사용자가 실수로 Esc를 눌렀을 때 위험한 작업이
실행된다. 게임의 결제 확인창에서 취소가 기본값이어야 하는 것과 같다.

표시 문구를 UI가 다시 만들지 않는 이유는 Phase 4와 같다. **화면에 보인 것과 실제 실행되는
것이 달라지는 경로**를 안 만드는 것이다.

### 복구가 끝날 때까지 입력을 안 받는다 (P8-05)

시작 시 복구 절차가 끝나기 전에는 일반 입력을 받지 않는다. 미완료 세션/작업/실행 중이던
단계를 구분해서 보여준다.

게임에서 세이브 로드가 끝나기 전에 조작을 받으면 안 되는 것과 같다. 여기서는 복구 중에 새
작업을 시작하면 Phase 5의 중복 실행 방어가 무의미해진다.

알림 규칙:

- 완료 알림에 민감한 결과 본문을 넣지 않는다
- 오류 알림은 사용자용 메시지만 보여주고 상세는 로그 링크로
- 마이크 사용 중 표시는 트레이와 입력 창 **양쪽에** 표시한다

Windows 알림은 알림 센터에 계속 쌓인다. 거기에 대화 내용이나 파일 내용이 남으면 안 된다.

### 자동 시작은 opt-in이고 도구가 아니다 (P8-06)

- 자동 시작은 **AI가 쓸 수 있는 도구가 아니라** 설치/UI 설정 기능이다
- 레지스트리 직접 수정 금지
- enable/disable을 대칭적으로 제공
- 제거할 때 자동 시작 항목도 제거
- 자동 시작 실패가 수동 실행을 막지 않는다

"AI가 쓸 수 있는 도구가 아니다"가 핵심이다. AI가 자기 자동 시작을 켤 수 있으면 안 된다.
사용자가 설정에서 직접 켜야 한다.

레지스트리 직접 수정을 금지한 것도, 제거 시 흔적이 남아서 "삭제했는데도 계속 실행되는 앱"이
되는 걸 막는 것이다.

### 패키징은 한 명령으로 재현 가능하게 (P8-07)

```powershell
scripts\build.ps1
```

| 규칙 | 이유 |
|------|------|
| 앱·스키마·프롬프트·설정 템플릿 버전을 매니페스트에 기록 | 나중에 "어느 버전이었나" 추적 |
| 시크릿·운영 설정·운영 DB·원본 로그를 패키지에 넣지 않음 | 내 데이터가 배포 파일에 들어가면 안 됨 |
| 새 Windows 사용자 프로필에서 처음부터 테스트 | 내 PC에만 있는 파일에 의존하는지 확인 |
| 기존 데이터가 있으면 덮어쓰지 않고 마이그레이션 | 업데이트로 데이터가 날아가면 안 됨 |
| 이전 버전으로 롤백할 때 DB 스키마 호환성 먼저 검사 | 신버전 세이브를 구버전이 못 읽음 |

"새 프로필에서 테스트"는 게임에서 **클린 머신 설치 테스트**와 같다. 개발 PC에는 온갖 SDK와
런타임이 깔려 있어서, 개발자 PC에서 되는 빌드가 유저 PC에서 안 도는 건 흔한 일이다.

마지막 항목도 중요하다. 신버전이 DB 스키마를 올려놨는데 구버전으로 롤백하면 구버전은 그
DB를 읽지 못한다. 게임에서 세이브 포맷을 올린 뒤 이전 패치로 되돌릴 수 없는 것과 같다.
그래서 롤백 전에 호환성을 먼저 검사한다.

## 5. 진입 전에 정해야 하는 것

| 결정 | 내용 | 상태 |
|------|------|------|
| D013 | Windows 패키징 방식 (PyInstaller 또는 대안) | pending |
| D014 | 트레이·전역 단축키 라이브러리 | pending |
| D015 | 자동 시작 설치 방식 | pending |

**세 개가 다 미정이라 이 Phase는 시작할 수 없다.** 게임에서 인스톨러 솔루션을 안 정하고
출시 준비를 시작할 수 없는 것과 같다.

## 6. 다 됐는지 확인하는 방법

```powershell
python scripts\gate.py --phase 8
pytest tests\slow\test_packaged_bootstrap.py
```

- [ ] 단축키로 입력 창과 PTT 호출
- [ ] 단일 인스턴스·중복 단축키 차단
- [ ] 마이크 상태가 항상 표시됨
- [ ] 승인 상태와 실제 실행 상태 일치
- [ ] Windows 재시작 뒤 복구 목록 표시
- [ ] 패키징된 앱에서 초기화·마이그레이션 성공
- [ ] v1 후보 매니페스트 작성

테스트 항목 중에 **"패키지에 `.env`, 실제 설정 사본, DB, 원본 로그가 없음"** 이 있다.
빌드 산출물에 개인 데이터가 섞여 들어가는지 자동으로 검사하는 것이다.

## 7. 이번엔 안 하는 것

- 화면을 보고 임의로 클릭하는 기능
- 숨겨진 상시 녹음
- UI 전용 정책 예외
- 운영 데이터를 설치 패키지에 포함
