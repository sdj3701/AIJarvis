## 1. 한 줄 요약

앱을 껐다 켜도 자비스가 나를 기억하고, 중요한 질의응답 지식을 정리해 보관한다. 이 지식은 Phase 3의 **로컬 RAG 선조회 캐시**로 연결되어 빠른 답변을 돕는다. 단, **AI가 멋대로 기억을 확정하지 못하게** 하고 사용자가 언제든 확인·수정·삭제·내보내기를 할 수 있게 만든다.

## 2. 게임으로 치면

세이브 데이터에 영구 진행 상황과 도감(Knowledge Base)을 저장하는 단계다.

- 퀘스트 상태 머신 (`미수락 → 진행중 → 완료`)
- 몬스터/아이템 도감 및 팁 데이터 축적 (RAG 지식 캐시)
- 업적 플래그
- 아이템 인벤토리 DB
- 세이브 슬롯 마이그레이션
- 자동 저장 체크포인트

특히 **상태 머신**이 이 Phase의 뼈대다.

## 3. 기억의 상태 머신

```text
AI 요약 → candidate(후보)
candidate + 사용자 확인 → confirmed(확정)
candidate + 사용자 거부 → deleted(삭제)
confirmed + 교정 → superseded(대체됨) + 새 confirmed
confirmed/candidate + /forget → deleted
```

| 상태 | 뜻 | 게임에서 같은 것 |
|------|-----|------------------|
| `candidate` | AI가 추측한 후보. 아직 사실 아님 | 퀘스트 목표 후보 (미수락) |
| `confirmed` | 사용자가 인정한 사실 | 수락된 퀘스트 / 획득한 업적 |
| `superseded` | 새 값으로 교체된 옛 기록 | 이전 버전 세이브 (지우지 않고 남김) |
| `deleted` | 삭제 표시 (tombstone) | soft delete. 실제 행은 남기고 숨김 |

### AI가 붙인 신뢰도는 확정 근거로 절대 안 쓴다

문서에서 가장 강하게 못 박은 규칙이다. AI가 "이거 95% 확실해요"라고 해도 그건 정렬·표시용
숫자일 뿐이고, **확정은 사람만 한다.**

이유는 게임 개발자면 바로 이해할 것이다. AI가 "이 유저는 하드코어 플레이어인 것 같다"고
추측해서 난이도를 영구적으로 올려 버리면, 틀렸을 때 되돌릴 방법이 없다. 추측을 사실로
승격시키는 자동 경로를 애초에 만들지 않는다.

## 4. 규칙별로 "왜 이렇게 하는가"

### 같은 항목의 확정 기억은 하나만 (P2-01)

`key`(예: "선호하는 언어")마다 `confirmed` 레코드는 딱 하나만 존재할 수 있다. 트랜잭션과
DB 인덱스 **양쪽으로** 보장한다.

코드 로직만으로 막으면 버그·경쟁 상태에서 중복이 들어간다. DB 제약을 같이 걸어두면 코드가
틀려도 DB가 거부한다. 게임에서 아이템 중복 지급을 서버 로직과 DB 유니크 키로 이중 방어하는
것과 같다.

### 같은 ID로 두 번 저장해도 중복이 안 생긴다 (P2-01)

멱등성이다. 네트워크 재시도나 크래시 복구로 같은 저장 요청이 두 번 들어와도 결과는 한 건이다.
인앱결제 영수증 처리와 완전히 같은 문제다.

### 교정할 때 옛 기록을 지우지 않는다 (P2-03)

```text
"틀림: A → B"
  → 기존 confirmed A를 superseded로 표시
  → 새 confirmed B(교정) 생성
```

옛 기록을 덮어쓰지 않고 남긴다. **"왜 자비스가 저렇게 알고 있지?"를 추적할 수 있어야 한다.**
게임에서 밸런스 값 변경 이력을 남기는 것, 또는 버전 관리로 이전 값을 볼 수 있게 하는 것과
같은 목적이다.

### key를 확신할 수 없으면 저장하지 말고 되묻는다 (P2-03)

"기억해: 나 파이썬 잘 몰라"라고 했을 때 이게 어떤 항목인지 애매하면, 추측해서 저장하지 않고
사용자에게 확인한다. 잘못된 key로 저장된 기억은 나중에 찾아서 고치기가 매우 어렵다.

### 삭제는 한 트랜잭션으로 전부 (P2-07)

`/forget`은 아래를 **하나의 트랜잭션**에서 처리한다.

1. 상태를 `deleted`로 바꾸고 tombstone 기록
2. 전문 검색 인덱스에서 제거
3. 있으면 임베딩에서도 제거
4. 삭제 이벤트 기록

하나라도 실패하면 전부 롤백한다.

왜 이렇게까지 하나? **본문은 지웠는데 검색 인덱스에 남으면 검색 결과로 튀어나온다.**
게임에서 아이템을 인벤토리에서 지웠는데 UI 캐시에 남아서 클릭하면 크래시하는 것과 같은
종류의 버그다. 그리고 이건 개인정보라서 훨씬 심각하다.

### 검색 랭킹을 순수 함수로 만든다 (P2-02)

점수 계산(가중치, 시간 감쇠, 동점 처리)을 부수 효과 없는 함수로 분리한다. 입력이 같으면
출력이 항상 같다.

이유는 테스트다. 랭킹 함수가 DB나 시계를 직접 만지면 "이 쿼리는 왜 이 순서로 나오나"를
단독으로 검증할 수 없다. 게임에서 데미지 계산식을 순수 함수로 빼놓고 유닛 테스트하는 것과
같다.

`deleted`와 `superseded`는 검색에서 제외한다. `candidate`는 확정 기억과 섞지 않고 별도
리스트로, 설정한 개수만 돌려준다.

### 요약 후보에는 반드시 근거 턴 ID를 요구한다 (P2-04)

AI가 "이 사용자는 게임 개발자다"라는 후보를 만들면, **몇 번째 대화에서 그렇게 판단했는지**
ID를 같이 내야 한다. 근거 없는 후보는 거부한다.

출처 없는 주장을 못 하게 만드는 장치다. 나중에 사용자가 "이건 왜 이렇게 기억했어?"라고
물으면 실제 대화를 보여줄 수 있다.

### 요약이 실패해도 세션 종료는 성공시킨다 (P2-04)

AI가 이상한 형식으로 답해서 요약이 실패해도, `/bye`(세션 종료) 자체는 정상으로 끝낸다.
실패는 이벤트로만 남긴다.

부가 기능 실패가 주 기능을 막아선 안 된다. 게임 종료 시 통계 전송이 실패했다고 게임이 안
꺼지면 곤란하다.

### 후보 기억은 프롬프트에서도 분리한다 (P2-05)

확정 기억과 후보 기억을 다른 블록에 넣고, 후보는 "아직 확정 안 된 정보"라고 시스템 지시로
명시한다. 그래야 AI가 후보를 사실처럼 단정하지 않는다.

프롬프트 예산을 넘으면 점수 낮은 것부터 뺀다. 여기도 버짓 관리다.

### N턴마다 체크포인트를 커밋한다 (P2-06)

설정한 턴 수마다 진행 상황을 DB에 커밋한다. 오토세이브다.

앱이 죽으면 다음 시작 때 순서대로 검사한다.

```text
임시/격리 파일 점검 → DB 무결성 검사 → 미완료 세션 → 진행 중이던 작업
```

복구 정책은 세 가지 중 하나로 설정한다.

| 정책 | 동작 |
|------|------|
| `prompt` | 사용자에게 물어본다 |
| `auto` | 자동으로 이어서 복구 |
| `discard` | 버린다 |

게임에서 "이전 세션이 비정상 종료됐습니다. 마지막 체크포인트에서 이어하시겠습니까?"를
띄우는 것과 같다.

## 5. 사용자 명령

| 명령 | 하는 일 |
|------|---------|
| `기억해: ...` | 사용자가 직접 확정 기억 생성 |
| `틀림: A → B` | 교정. 옛 기록은 대체 표시 |
| `/memory list` | 상태·종류 필터로 목록 조회 |
| `/memory confirm <id>` | 후보를 확정으로 승격 |
| `/memory edit <id>` | 기존 것을 대체하고 새로 생성 |
| `/forget <id>` | soft delete + 인덱스 제거 |
| `/memory export` | JSON으로 내보내기 |

내보내기 기능이 있는 이유는, **사용자가 자기 데이터를 가져갈 수 있어야** 한다는 원칙이다.
게임 세이브 파일을 유저가 백업할 수 있는 것과 같다.

## 6. 다 됐는지 확인하는 방법

```powershell
python scripts\gate.py --phase 2
python scripts\gate.py --report
```

- [x] 같은 항목의 확정 기억 두 개 생성이 거부된다
- [x] 교정이 다른 항목의 순위에 영향을 주지 않는다
- [x] 후보를 사실처럼 단정하지 않는다
- [x] `/forget` 후 본문·검색 인덱스에서 전부 사라진다
- [x] 재시작 후에도 선호가 반영된다
- [x] 근거 턴 없는 후보가 거부된다
- [x] 기억 질의 정확도 90% 이상 (`memory_eval.jsonl` 평가셋)

정확도 90%는 자동 평가셋으로 측정한다. 게임에서 AI 밸런스를 감으로 판정하지 않고 자동
시뮬레이션 배틀 승률로 판정하는 것과 같은 방식이다.
